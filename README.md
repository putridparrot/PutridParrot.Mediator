# PutridParrot.Mediator

A lightweight implementation of the Mediator pattern for .NET, with optional source generator support.

## Features

- ? Simple and intuitive API
- ? Support for requests with and without responses
- ? Built-in dependency injection integration
- ? Source generator for automatic handler registration
- ? Pipeline behaviors (logging, caching, or your own) for cross-cutting concerns
- ? Async/await support with CancellationToken
- ? Minimal dependencies

## Installation

```bash
dotnet add package PutridParrot.Mediator
```

The package includes the source generator, so there is nothing else to install.

## Quick Start

### 1. Define Requests and Handlers

**Request with Response (Query):**
```csharp
public record GetUserRequest(int Id) : IRequest<UserDto>;
public record UserDto(int Id, string Name);

public class GetUserHandler : IRequestHandler<GetUserRequest, UserDto>
{
    public Task<UserDto> Handle(GetUserRequest request, CancellationToken cancellationToken = default)
    {
        // Fetch user from database
        return Task.FromResult(new UserDto(request.Id, $"User {request.Id}"));
    }
}
```

**Request without Response (Command):**
```csharp
public record CreateUserCommand(string Name, string Email) : IRequest;

public class CreateUserCommandHandler : IRequestHandler<CreateUserCommand>
{
    public Task Handle(CreateUserCommand request, CancellationToken cancellationToken = default)
    {
        // Save user to database
        Console.WriteLine($"Creating user: {request.Name}");
        return Task.CompletedTask;
    }
}
```

### 2. Register Services

**Option 1: Auto-register handlers from assemblies**
```csharp
services.AddMediator(typeof(Program).Assembly);
```

**Option 2: Manual registration**
```csharp
services.AddMediator();
services.AddTransient<IRequestHandler<GetUserRequest, UserDto>, GetUserHandler>();
services.AddTransient<IRequestHandler<CreateUserCommand>, CreateUserCommandHandler>();
```

**Option 3: Using the generated registration (no assembly scanning)**
```csharp
services.AddMediator();
services.AddGeneratedRequestHandlers(); // Generated by the source generator for this project
```

`AddGeneratedRequestHandlers` registers the request and stream handlers in the current project together
with its generated dispatchers. It is `internal`, so each project has its own and they never clash.
Notification handlers are not included; register them yourself or use assembly scanning (Option 1).

The mediator is registered as transient, so handlers are resolved from the current scope and can depend
on scoped services such as an EF Core `DbContext`.

### 3. Use the Mediator

```csharp
public class UserController
{
    private readonly IMediator _mediator;
    
    public UserController(IMediator mediator)
    {
        _mediator = mediator;
    }
    
    public async Task<UserDto> GetUser(int id)
    {
        var request = new GetUserRequest(id);
        return await _mediator.Send(request);
    }
    
    public async Task CreateUser(string name, string email)
    {
        var command = new CreateUserCommand(name, email);
        await _mediator.Send(command);
    }
}
```

## Pipeline Behaviors

Pipeline behaviors wrap request handling, so you can add cross-cutting concerns such as logging,
caching, validation or timing without changing your handlers. Behaviors are resolved from
dependency injection when a request is sent and work with or without the source generator.

### Registering behaviors

Declare behaviors when adding the mediator. They run in the order they are added; the first
behavior added is the outermost, so it runs first before the handler and last after it.

```csharp
services.AddLogging();
services.AddMemoryCache();

services.AddMediator(cfg =>
{
    cfg.RegisterServicesFromAssembly(typeof(Program).Assembly);

    // Open generic behaviors apply to every request
    cfg.AddOpenBehavior(typeof(LoggingPipelineBehavior<,>));
    cfg.AddOpenBehavior(typeof(CachingBehavior<,>));

    // Closed behaviors apply only to the request types they implement
    cfg.AddBehavior<GetUserAuditBehavior>();
});
```

Behaviors are transient by default; set `cfg.BehaviorLifetime` before adding behaviors to change this.
Behaviors registered directly with `services.AddTransient(typeof(IPipelineBehavior<,>), ...)` also work.

### Writing a behavior

```csharp
public class TimingBehavior<TRequest, TResponse> : IPipelineBehavior<TRequest, TResponse>
    where TRequest : IRequest<TResponse>
{
    public async Task<TResponse> Handle(
        TRequest request,
        RequestHandlerDelegate<TResponse> next,
        CancellationToken cancellationToken)
    {
        var start = Stopwatch.GetTimestamp();
        var response = await next();
        Console.WriteLine($"{typeof(TRequest).Name} took {Stopwatch.GetElapsedTime(start).TotalMilliseconds:F2}ms");
        return response;
    }
}
```

### Built-in behaviors

- **`LoggingPipelineBehavior<,>`** logs each request at Debug level and failures at Error level.
  `services.AddMediatorLogging()` is a shortcut that registers it for all requests.
- **`CachingBehavior<,>`** caches responses in `IMemoryCache` for requests implementing
  `ICacheableRequest<TResponse>`; other requests pass straight through. Requires `services.AddMemoryCache()`.

```csharp
public record GetUserQuery(int Id) : IRequest<UserDto>, ICacheableRequest<UserDto>
{
    public string GetCacheKey() => $"user:{Id}";
    public TimeSpan GetCacheExpiration() => TimeSpan.FromMinutes(5);
}
```

## Notifications

Notifications are published to every registered `INotificationHandler<T>`, one at a time in registration
order. Assembly scanning (`AddMediator(assemblies)`) registers notification handlers automatically.

```csharp
public record OrderCreated(int OrderId) : INotification;

public class SendConfirmationEmail : INotificationHandler<OrderCreated>
{
    public Task Handle(OrderCreated notification, CancellationToken cancellationToken = default)
    {
        // Send the email
        return Task.CompletedTask;
    }
}

await mediator.Publish(new OrderCreated(42));
```

By default every handler runs even if an earlier one fails, and the failure is then rethrown
(as an `AggregateException` if several handlers failed). Choose a different strategy when adding the mediator:

```csharp
services.AddMediator(cfg =>
{
    cfg.RegisterServicesFromAssembly(typeof(Program).Assembly);
    cfg.NotificationErrorHandling = NotificationErrorHandling.LogAndContinue;
});
```

| Strategy | Behavior |
|----------|----------|
| `ThrowAfterAllHandlers` (default) | Run every handler, then rethrow the failure(s) |
| `StopOnFirstException` | Rethrow the first failure immediately; later handlers don't run |
| `LogAndContinue` | Log failures with `ILogger` and never throw |

Cancellation always stops publishing immediately.

## Architecture

The mediator pattern helps to:
- **Reduce coupling** between components
- **Centralize** request/response handling logic
- **Simplify** testing and maintenance
- **Organize** application logic using CQRS principles

### Request Flow
```
Controller ? IMediator.Send() ? IRequestHandler.Handle() ? Response
```

## API Reference

### Interfaces

#### `IRequest<TResponse>`
Marker interface for requests that return a response.

#### `IRequest`
Marker interface for requests without a response (commands).

#### `IMediator`
```csharp
Task<TResponse> Send<TResponse>(IRequest<TResponse> request, CancellationToken cancellationToken = default);
Task Send(IRequest request, CancellationToken cancellationToken = default);
Task Publish(INotification notification, CancellationToken cancellationToken = default);
IAsyncEnumerable<TResponse> CreateStream<TResponse>(IStreamRequest<TResponse> request, CancellationToken cancellationToken = default);
```

#### `IRequestHandler<TRequest, TResponse>`
```csharp
Task<TResponse> Handle(TRequest request, CancellationToken cancellationToken = default);
```

#### `IRequestHandler<TRequest>`
```csharp
Task Handle(TRequest request, CancellationToken cancellationToken = default);
```

## Source Generator

The source generator runs automatically in any project that references the package. It discovers classes
implementing `IRequestHandler<,>`, `IRequestHandler<>` or `IStreamRequestHandler<,>` and generates:

- Strongly-typed dispatchers that invoke handlers without reflection
- The `AddGeneratedRequestHandlers()` registration method

`AddMediator(assemblies)` picks up the generated dispatchers automatically, including from several
assemblies. Any handler the generator can't see (for example in a project without the generator, or a
private nested class) still works through a reflection fallback.

Benefits:
- No reflection when invoking handlers
- Compile-time handler discovery
- Better performance

## Best Practices

1. **Use records for requests** - They're immutable and perfect for data transfer
2. **Keep handlers focused** - One handler per request type
3. **Use CancellationToken** - For proper async cancellation support
4. **Separate queries and commands** - Follow CQRS principles
5. **Inject dependencies into handlers** - Not into requests
